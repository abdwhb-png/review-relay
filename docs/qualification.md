The native OpenCode scenario delivered explicit `CLAUDE.md` and glob instructions to the actual model request, exported/imported a native session, retained earlier context, switched providers, observed high reasoning on primary and fallback requests, applied a project medium override and refused an attempted shell execution. Native suggestion scenarios verified the frozen commit, frozen instruction reads and publication without model credentials. Native fixtures used finite PyGithub HTTP responses and a local model stub, without external network access after native tokenizer preparation.

These results do not qualify arbitrary provider integrations, sandbox escape resistance or live OpenRouter inference. Manual fallback has deterministic lifecycle coverage and real pinned-client coverage against a local transport; no live OpenRouter qualification is claimed. Reviewed consumer code was inspected without execution by either review engine.

## Release gate

Complete both hosted paths against the frozen runtime candidate before tagging. Keep consumer evidence private and verify publication on the exact reviewed commits. Any runtime, workflow, native profile or dependency change invalidates the affected qualification and requires a new candidate. A release commit may add only documentation of completed evidence; verify that its executable files and configuration are identical to the qualified candidate before creating the version tag. Neither an approved design nor local fixture results alone establish a qualified release.
